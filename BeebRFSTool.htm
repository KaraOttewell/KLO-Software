BeebRFSTool

Command-line tool for packing and extracting BBC Micro ROM Filing System images

Windows Command Line Microsoft Store BBC Micro Free

BeebRFSTool is a Windows command-line tool for packing files into BBC Micro ROM Filing System (RFS) sideways ROM images, and extracting, or just listing, files from them. It handles both RFS formats: compressed, compatible with the comprom.pl v2.10 format created by Greg Cook, and standard, uncompressed RFS. When extracting, the format is worked out from the ROM header, so you never have to say which kind you have.

BeebRFSTool uses the same compression and extraction engine that powers the BeebRFSMaker Windows WinUI 3 application, but it is designed to be used completely standalone in a cmd terminal — no GUI app installation is required.

The most up to date version of this information will always be the online version.

Usage

C:\LocalOnly\RFS> BeebRFSTool --help
BeebRFSTool v2026-09-13_22:50 — BBC Micro ROM Filing System (RFS) Pack, List, and Extract Tool by Kara Ottewell
Reads and writes standard RFS, Greg Cook's "comprom" v2.10, and KLOComp Lempel-Ziv ROM images


BeebRFSTool <command> [options]

Description:
  Packs files from this PC into a BBC Micro ROM Filing System (RFS) ROM image, or lists and
  extracts the files held in one that already exists. Images are 16 KB sideways ROMs, ready to
  burn for a real BBC Microcomputer or to load into an emulator.

  pack     <input-dir> <rom.bin>   Pack every file in the folder into a new ROM image, in any
                                   of the three formats. See --compress below.

  extract  <rom.bin> <output-dir>  Write the files held in the ROM image out into the folder.
                                   All three formats are read: standard RFS, comprom, and
                                   KLOComp Lempel-Ziv.

Pack options:

  --romtitle <string>      ROM header title, as shown by *ROMS, e.g. "My Tools".

  --catalogtitle <string>  Empty file acting as a title, shown by *CAT, so "MyTools" is listed
                           as *MyTools*. Written by the comprom format only.

  --copyright <string>     Copyright string, e.g. "1.00".

  --versionstring <string> Version string, e.g. "2.10 (14 Oct 2022)".

  --compress=<how>         comprom, lz77, or none. comprom is Greg Cook's v2.10 format and the
                           default. lz77 is KLOComp Lempel-Ziv, which holds more still. none
                           builds a standard RFS ROM with nothing to decode at run time, which
                           holds the least but can be read by any tool.

Extract options:

  --inf or -i              Write a .INF sidecar beside each extracted file, recording its BBC
                           name, load and execution addresses, length and lock state.

  --list or -l             List what the ROM image holds and write nothing, so no output folder
                           is needed. A listing can only be a listing of a ROM image, so the
                           extract command may be left out: beebrfstool MyROM.rom --list.

General options:

  --colour=<when>          always, never, or auto, the default. Colour is normally asked of the
  --color=<when>           console, which ignores it when the output is redirected, so a captured
                           run is plain text. always writes the colour into the stream itself,
                           which is how to keep the colours of a run in a file.

  --help or -h             Display this help. Add examples, as in --help examples, to see a
                           handful of worked command lines after it.

Worked examples from the tool itself

Adding the word examples to --help prints a handful of worked command lines after the reference list, so the common shapes can be copied without leaving the terminal. The reference list is the same one shown above and is elided here.

C:\LocalOnly\RFS> BeebRFSTool --help examples
     ... the reference list above ...

Examples:
    1) See what is inside a ROM image, without writing anything
         beebrfstool MyROM.rom --list
    2) Extract the files, with a .INF sidecar beside each one so the
    load and execution addresses are not lost
         beebrfstool extract MyROM.rom .\out --inf
    3) Pack a folder of files into a comprom ROM image, naming it
    as it will appear to *ROMS and *CAT on the BBC
         beebrfstool pack .\MyFiles MyROM.rom --romtitle "My Tools" --catalogtitle MyTools
    4) Pack the same folder as a Lempel-Ziv ROM, which holds the most, or
    as a standard RFS ROM, which holds the least but needs no decoding
         beebrfstool pack .\MyFiles MyROM.rom --compress=lz77
         beebrfstool pack .\MyFiles MyROM.rom --compress=none
    5) Keep the colours of a listing in a file, rather than losing them
    the moment the output is redirected
         beebrfstool MyROM.rom --list --colour=always > run.txt 2>&1

The examples are kept behind that word rather than always shown, because the reference list already runs to more than a screenful and most runs are looking something up in it rather than starting from nothing.

Example: packing files

Pack a folder of BBC Micro files into a 16 KB sideways ROM image. Files with a matching .inf sidecar file (a file in the same folder with the same name plus a .inf extension) will have their BBC Micro filename, load address, and execution address set according to the metadata in that file. Any file without a matching sidecar defaults to a sanitised, legal Beeb filename, with a load and exec address set to &0000 and the length taken from the PC file length, unless it is detected as a tokenised BBC BASIC binary, in which case the load address is set to &1900 and the exec address to &8023.

C:\LocalOnly\RFS> BeebRFSTool pack .\TestFiles TestComprom.rom --romtitle "Test Tools" --catalogtitle "TestTools"

Example: extracting files

Extract all files from an existing RFS ROM image, giving the ROM to read and the folder to write into. The -i flag generates .inf sidecar files alongside each extracted file, preserving the BBC Micro filename, load address, execution address, and file length. Use -l instead to list a ROM's contents without writing anything to disk. Either way the run finishes with a *INFO style catalogue of the files and a one-line summary of the ROM's own header.

The closing list is a *INFO style catalogue, one line per file: the BBC Micro filename, its load address, execution address and length, and then in parentheses the name the file is given on this PC. The two differ whenever a BBC name contains characters Windows will not accept in a filename. Here the catalogue entry *TestTool* becomes TestTool, since Windows filenames cannot contain asterisks. The catalogue title was given as TestTools, and is shown clamped to the eight characters that fit between the asterisks.

Defende comes back out marked Locked, because the .inf file packed alongside it said so. The protection bit is carried through the ROM image and written back into the .inf on the way out, so a file that was locked before packing is still locked afterwards.

The final line summarises the ROM's own header: its title, version string and copyright, whether it is compressed or plain RFS, and the paged-ROM header fields — the type byte (spelled out in parentheses), the binary version number, and the language and service entry addresses. A filing system ROM is type &82: it offers a service entry but has no language of its own. Note that the compressed ROM's language entry points at &811C whereas the plain one shows &0000, the unused entry described below.

Each extracted file is written to the output folder under the name shown in parentheses. With -i, a corresponding .inf file is written alongside it, for example:

DefenMC 00001900 00000E00 002300
in the standard format.

Example: standard, uncompressed ROMs

--compress=none writes a plain RFS ROM instead of a compressed one. The files are stored verbatim, so there is no dictionary, no digraph table and no decompressor stub. The ROM holds a good deal less, but its layout is straightforward and nothing has to be decoded at run time. The same six files that filled 78% of the ROM under comprom fill 89% here.

Example: KLOComp Lempel-Ziv ROMs

--compress=lz77 writes a KLOComp Lempel-Ziv ROM, which holds more than either of the other two. Each file is compressed on its own as an LZ77 stream over a 192-byte window, so reaching the last file does not mean expanding the ones before it, and a file that would grow is stored as it stands and marked with an asterisk. The saving over comprom comes from carrying no dictionary, a smaller decompressor stub, and block headers that are worked out as the MOS asks for them rather than being stored.

C:\LocalOnly\RFS> BeebRFSTool pack .\TestFiles TestLZ77.rom --romtitle "Test LZ77" --compress=lz77

Features

Pack files into ROM images

Pack a folder of files into a standard 16 KB sideways ROM image, with optional ROM title, catalogue title, copyright, and version string.

Three RFS formats

Produce a comprom (CompRFS) ROM, a KLOComp Lempel-Ziv ROM, or a standard plain RFS ROM from the same folder of files, choosing with --compress=comprom, --compress=lz77 or --compress=none. All three are read back without being told which is which.

Extract from ROM images

Extract files from any compatible RFS ROM image, compressed or uncompressed — the format is detected from the ROM header — with optional .inf sidecar generation preserving BBC Micro metadata.

*INFO style catalogue

Every extract or list run ends with a catalogue of the files — BBC filename, load and execution addresses and length, with the name used on this PC alongside — and a one-line summary of the ROM header, including the type byte spelled out in plain English.

Compression feedback

Detailed output shows per-file raw and compressed sizes, dictionary and digraph statistics, and overall ROM utilisation.

comprom.pl compatible

Produces byte-identical ROM images to the original comprom.pl v2.10 Perl script by Greg Cook, requiring no Perl installation.

Scripting and automation

Designed for use in batch files and build pipelines. Error messages are written to standard error and normal output to standard output, and meaningful exit codes are returned.

.inf sidecar support

Reads and writes .inf sidecar files in the standard BBC Micro format used by DFS tools, preserving load addresses, execution addresses, and BBC filenames. Addresses are written as eight hex digits, so a host address such as FFFF1900 is stated in full; the shorter four- and six-digit forms written by other tools are still read.

Disk image file names

A folder of files exported from a .ssd or .dsd disk image packs under the BBC names they had. The drive and directory that 0_$.MAKERFS and 0_P.MakeRFS carry are stripped off, since a ROM filing system has no directories, and a name never keeps a dot — which the BBC would read as a directory separator.

Download and Install

BeebRFSTool

The app can be installed from:

  • The Microsoft Store web page
  • The Microsoft Store app

Requires Windows 10 or later and .NET 9 or later.

Note: If you need a graphical interface rather than a command line, BeebRFSMaker provides the same packing and extraction functionality as a WinUI 3 Windows application.

Compatibility

BeebRFSTool handles both the Compressed ROM Filing System v2.10 format and standard, uncompressed RFS. ROM images it produces can be used with:

  • A real BBC Micro Model B, B+, or Master 128 with a suitable ROM board
  • BeebEm and other BBC Micro emulators that support sideways ROMs
  • Any other tool that reads the comprom.pl v2.10 format

When reading an uncompressed ROM, the unused language entry point at &8000 may be filled with either three NOP instructions or three zero bytes; both conventions are recognised. Either way there is no address to report, which is why the ROM summary shows a language entry of &0000 for a plain RFS ROM.
